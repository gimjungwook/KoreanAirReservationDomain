문제

발생원이 셋으로 늘면 호출자가 비대해진다.

iter2 · BookingController.confirmPayment
if (payment.getStatus() == PaymentStatus.PAID) {
    reservation.addPayment(payment);
    reservation.processPayment();
} else {
    reservation.handlePaymentFailure();   // 호출자가 부수효과 책임
}

iter3에서 같은 "자동 취소"가 필요한 발생원

  • 1좌석 hold 15분 만료 — SeatHoldMonitor가 발견
  • 2결제 실패 — PaymentProcessor가 발견
  • 3FlightSchedule 취소 — 관리자 명령
  • 호출자가 N배로 비대해진다
  • 같은 코드가 세 곳에 복제된다
  • 새 발생원마다 호출자 수정 → OCP 위반
호출자 = 자기 책임 아닌 후속 처리까지 떠안음해법: 발생원을 Subject로, 부수효과를 Listener로
