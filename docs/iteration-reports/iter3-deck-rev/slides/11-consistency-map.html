하나의 요구사항이 UC → Sequence → Class → State를 거쳐 같은 코드 한 줄로 떨어진다.

✓ Sequence → 빠진 객체·메서드 검증

시퀀스를 그리며 missing class · missing behavior(method)를 찾아낸다. 참여자는 모두 구체 ECB 객체 — 추상 "System" 금지

✓ State = 한 object의 상태

한 object의 attribute 값 변화에 따른 전이만 표현. 전이 메서드(handlePaymentFailure)가 Class의 listener 호출과 일치

✓ Control이 use case를 realize

UC 하나를 control object 하나가 실현. Functional → Analysis Object → Dynamic 모델로 일관 추적

분석 모델 목표: Correct · Complete · Consistent · Unambiguous같은 시나리오를 보고 두 사람이 다르게 해석하면 안 된다
