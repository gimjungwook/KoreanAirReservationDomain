State · Strategy · Observer는 충돌하지 않는다.

ITERATION 1
State
상태 축
예약이 어떤 전이를 할 수 있는가. 생애주기 가드.
ITERATION 2
Strategy
알고리즘 축
환불 금액을 어떻게 계산하는가. RefundPolicy family.
ITERATION 3
Observer
통지 축
상태 변화의 부수효과를 누구에게 통지하는가.
실제로 iter3 listener가 부르는 Reservation.handlePaymentFailure()는 iter1 State 전이이고, 그 시점에 iter2 Strategy(RefundPolicy)가 잠재적으로 함께 동작한다. 세 반복이 교체가 아니라 누적된 하나의 시스템이라는 증거다.
축이 다르므로 한 클래스가 세 책임을 떠안지 않는다 (SRP)Observer는 State 위에, Strategy 옆에 — 직교한다
