Use Case 시나리오 — Iter 3 시연 5종 07 / 21
5 KEY SCENARIOS

발표 시연용 5개 흐름

각 시나리오는 발표 시 콘솔/Swing에서 끝까지 동작하는 단위. 3개 Observer + Connecting + Mileage.

SC-01 · OBSERVER
좌석 hold 만료 자동 해제
TRIGGER · scheduler.sweep()
  1. 회원이 좌석 선택 → Seat.hold(15, pnr)로 holdExpiresAt 세팅
  2. 결제 단계로 이동하지 않은 채 15분 경과
  3. SeatHoldMonitor.sweep()이 만료 좌석 감지
  4. SeatHoldExpiredEvent 발행 → listener가 release + handlePaymentFailure
  5. 좌석 Available, 예약 Cancelled로 종결
SC-02 · OBSERVER
결제 실패 자동 취소
TRIGGER · gateway.authorize() → false
  1. 회원이 결제 정보 입력 후 submitPayment 호출
  2. processPaymentCharge(amount, pnr) 실행
  3. gateway.authorize() 거절 → payment.fail()
  4. PaymentFailedEvent("gateway-declined") 발행
  5. AutoCancelListener가 PendingPayment → Cancelled
SC-03 · OBSERVER
FlightSchedule 변경 전파
TRIGGER · admin.changeFlightStatus(KE001, CANCELLED)
  1. 관리자가 항공편 취소 명령 입력
  2. FlightSchedule.changeStatus(CANCELLED) — 내부 publish
  3. FlightStatusChangedEvent가 prev/new status 담아 broadcast
  4. AffectedReservationListener가 registry에서 schedule 참조 예약 필터링
  5. 각 Reservation에 evaluateImpact 호출 + 콘솔 로그
SC-04 · ITINERARY
환승 일정 MCT 검증
TRIGGER · 사용자: ICN → JFK (date)
  1. UI가 searchConnecting(from, to, date, MCT) 호출
  2. catalog 순회로 a.dest == b.origin && b.dest == to 인 (a, b) 쌍 탐색
  3. 각 쌍을 Itinerary.connecting(a, b)로 래핑
  4. isConnectionTimeValid(MCT)로 layover ≥ 90분 검증
  5. 통과한 Itinerary만 결과 리스트에 추가
SC-05 · MILEAGE PAYMENT
마일리지 결제 + 잔액 부족 시 자동 취소
TRIGGER · 회원: payWithMileage(reservation, mileageCost)
  1. 회원이 결제 화면에서 "마일리지 결제" 선택, cost 입력
  2. BookingController.confirmMileagePayment(reservation, account, cost) 호출
  3. processMileagePayment — account.withdraw로 차감 시도 → 성공 시 payment.pay() + Reservation.processPayment 전이 (PendingPayment → Confirmed)
  4. 잔액 부족 시 PaymentFailedEvent("insufficient-mileage") 발행 → SC-02와 같은 listener로 자동 취소
