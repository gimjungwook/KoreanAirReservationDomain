6 KEY SCENARIOS

발표 시연용 6개 흐름

각 시나리오는 발표 시 콘솔/Swing에서 끝까지 동작하는 단위다. 앞의 4개는 Observer 적용 흐름, 뒤의 2개는 iter3 도메인 확장이다. 버스티켓 연계는 항공권 구매 완료 이벤트에 listener가 반응하는 핵심 시연으로 둔다.

SC-01 · OBSERVER
좌석 hold 만료 자동 해제
TRIGGER · scheduler.sweep()
  1. Seat.hold(15, pnr)로 holdExpiresAt 세팅
  2. SeatHoldMonitor.sweep()이 만료 좌석 감지 후 SeatHoldExpiredEvent 발행
  3. listener가 좌석 release + 예약 PendingPayment → Cancelled 처리
SC-02 · OBSERVER
결제 실패 자동 취소
TRIGGER · gateway.authorize() → false
  1. processPaymentCharge(amount, pnr)에서 gateway 승인 거절
  2. PaymentFailedEvent("gateway-declined") 발행
  3. AutoCancelListener가 같은 취소 로직으로 PendingPayment → Cancelled
SC-03 · OBSERVER
FlightSchedule 변경 전파
TRIGGER · admin.changeFlightStatus(KE001, CANCELLED)
  1. FlightSchedule.changeStatus(CANCELLED)가 prev/new status를 이벤트에 담아 publish
  2. AffectedReservationListener가 registry에서 해당 항공편 예약만 필터링
  3. 각 Reservation에 evaluateImpact 호출 + 영향 로그 출력
SC-04 · OBSERVER
항공권 구매 연계 우등고속 버스티켓 발매
TRIGGER · e-Ticket issued + bus city selected
  1. 항공권 발권 후 6개 대도시 중 버스 목적지 선택: 서울·부산·대구·광주·대전·인천
  2. TicketPurchasePublisher.publishTicketIssued(..., BusCity) 호출
  3. BusTicketPurchaseListener가 BusTicketingService.issuePremiumTicket 실행
SC-05 · ITINERARY
환승 일정 MCT 검증
TRIGGER · 사용자: ICN → JFK (date)
  1. searchConnecting(from, to, date, MCT)가 항공편 쌍 탐색
  2. Itinerary.connecting(a, b)로 묶고 layover ≥ 90분 검증
  3. 통과한 Itinerary만 UI 결과와 콘솔 로그에 표시
SC-06 · MILEAGE PAYMENT
마일리지 결제 + 잔액 부족 시 자동 취소
TRIGGER · 회원: payWithMileage(reservation, mileageCost)
  1. confirmMileagePayment(reservation, account, cost) 호출
  2. 성공 시 mileage 차감 + Reservation PendingPayment → Confirmed
  3. 잔액 부족 시 PaymentFailedEvent("insufficient-mileage") 발행 → SC-02 listener 재사용
